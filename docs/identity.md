# Identity and authorization modes

## Development demo mode

Set `APP_ENV=development`, `DEMO_MODE=true`, and `IDENTITY_MODE=demo`. The application creates a server-side demo session for `demo.viewer`, and the development-only selector can switch to `demo.operator`, `demo.approver`, or `demo.admin`. The selector is hidden outside demo mode; authorization is still enforced in service methods and direct routes.

## Microsoft Entra ID mode

Set `DEMO_MODE=false`, `IDENTITY_MODE=entra`, `ENTRA_TENANT_ID`, `ENTRA_CLIENT_ID`, `ENTRA_CLIENT_SECRET`, `ENTRA_REDIRECT_URI`, and a shared `SESSION_REDIS_URL`. Register a web application in the tenant, add the exact redirect URI (for example `https://app.example/auth/callback`), and grant the OpenID profile/email sign-in scopes. Use a certificate or secret stored outside source control.

Create app roles named `HarvestOps.Operator`, `HarvestOps.Approver`, and `HarvestOps.Admin`. The callback maps those claims to the internal `operator`, `approver`, and `admin` roles and always grants the authenticated principal `viewer`. Role claims are stored in the server-side session so multiple workers do not rely on process-local identity state. Production rejects demo identity and requires Redis-backed sessions.

`/auth/login` starts MSAL's supported `initiate_auth_code_flow` with an empty application-scope list. MSAL adds the reserved OpenID scopes and creates the nonce, PKCE verifier/challenge, and state-bound flow. HarvestOps explicitly requests `response_mode=query`, so the identity provider returns through a top-level GET. That is intentional: the server session cookie remains `SameSite=Lax`, the browser sends it on the cross-site top-level navigation, and the saved state/nonce/PKCE flow is recovered without broadly weakening cookie or CSRF protection. The flow is stored server-side; `/auth/callback` passes the exact flow to `acquire_token_by_auth_code_flow`, which validates the state, nonce, and PKCE exchange, regenerates the session identifier when the configured session interface supports it, and redirects back to the application after success. The accessible sign-out form posts a CSRF token to `POST /auth/logout`, which clears the server-side session. Local MSAL construction, callback, logout, and a two-site Playwright browser simulation are verified with mocked identity-provider responses. The browser test binds both endpoints locally but uses `localhost` for the app and `127.0.0.1` for the simulated identity provider, so it exercises a genuinely cross-site top-level GET rather than merely different ports on one site. It verifies cookie/state preservation and return to the app; live Microsoft Entra sign-in and tenant configuration remain account-dependent and unverified.
